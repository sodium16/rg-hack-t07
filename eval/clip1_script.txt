Welcome everyone to today's short lecture on supervised machine learning and how models learn from errors using gradient descent.

Let us start with the core definition. Supervised learning is a branch of machine learning where a model learns a mapping from input features to known output labels using a labelled dataset. Every example in that dataset has two parts: the features, which are the measurable inputs such as house size or number of bedrooms, and the label, which is the true answer we want the model to predict, such as the sale price.

When the model starts training, its internal parameters—which we usually call weights—are initialized to small random numbers. Because the weights start out random, the model's initial predictions are almost always wrong. To measure how wrong those predictions are, we define a loss function. A loss function is a mathematical formula that takes the model's predicted value and the true label, and outputs a single non-negative number representing the prediction error.

One of the most common loss functions for predicting continuous numbers is mean squared error. Mean squared error works by taking the difference between each predicted value and the actual value, squaring that difference so positive and negative errors do not cancel out, and then averaging those squared errors across all training examples.

A small loss means the predictions are close to the ground truth, while a large loss means the model is making big mistakes. Therefore, the goal of training a supervised model is straightforward: find the set of weights that minimizes the loss function across the entire training set.

Now, how does a model actually find the weights that minimize the loss? If we only had one or two weights, we might try guessing values on a grid. In modern models, however, there can be thousands or even billions of weights, so guessing is impossible. Instead, we use an optimization algorithm called gradient descent.

Gradient descent is an iterative optimization algorithm that updates the model's weights step by step in the direction that reduces the loss function the fastest. Imagine standing blindfolded on the side of a foggy valley and wanting to reach the lowest point. You cannot see the whole valley, but you can feel the slope right under your feet. If the ground slopes upward to your right, you take a step to your left.

In calculus, that slope is called the gradient. The gradient points in the direction of steepest increase of the loss function. Since we want the loss to go down rather than up, gradient descent moves in the direction of the negative gradient. At each step, we compute the gradient of the loss with respect to each weight, and then subtract a fraction of that gradient from the current weight.

That brings us to one of the most important settings in training: the learning rate. The learning rate is a hyperparameter that controls the size of the step we take during each weight update in gradient descent. Choosing the learning rate requires careful balance. If the learning rate is too small, the model takes tiny steps and training becomes painfully slow, requiring many passes through the dataset. On the other hand, if the learning rate is too large, the updates can overshoot the minimum altogether, causing the loss to bounce wildly or even diverge to infinity.

One full pass over the entire training dataset is called an epoch. During training, a model typically runs for dozens of epochs, gradually lowering the training loss. However, lowering the training loss forever is not actually our true goal. What we really care about is how well the model performs on new, unseen data after training finishes.

This leads to a classic failure mode called overfitting. Overfitting occurs when a model memorizes noise and specific quirks in the training dataset instead of learning the underlying general pattern, causing it to score very well on training data but poorly on unseen data. For example, if a model memorizes the exact prices of fifty houses in one neighbourhood, it may fail badly when asked to price a house in the next town.

To detect overfitting early, we split our available data before training starts. We hold out a separate portion called a validation set. A validation set is a subset of labelled data held back from training and used solely to evaluate the model's generalization performance and tune hyperparameters like the learning rate. If the training loss keeps falling while the validation loss starts rising, that is a clear warning sign that overfitting has begun, and we should stop training early.

Another tool we use to fight overfitting is regularization. Regularization is a technique that adds a penalty term to the loss function based on the size of the weights, discouraging the model from relying too heavily on any single feature. By penalizing overly complex weights, regularization encourages simpler solutions that generalize better to real-world inputs.

To wrap up: supervised learning pairs features with labels, measures mistakes with a loss function like mean squared error, adjusts weights using gradient descent scaled by a learning rate, checks generalization on a validation set, and uses regularization to prevent overfitting.
